## 0. 一句話結論

**兩項指示的答案是同一件事：把「呈現」與「治理權責」分層，而不是把內容搬走或把勞工項目往後推。**

v0.4.0 之後，原先阻擋 Level 1 的技術缺口**已經消失**，故 A 部與 B 部
**現可於同一批次執行完畢**，不再需要分批等待。

且因國健署已表示「嚼檳榔一併定案即同意 21 項」，而嚼檳之技術結構**已於 v0.4.0 落地**，
**M-5 之條件在技術面已告成就**——本 JOB 因此新增 §3.4「M-5 結案路徑」：
把「已定案」的具體內容做成可簽核的書面確認單送國健署，取得書面後 M-5 始得結案。
**在取得書面之前，不得逕行變更 M-5 狀態或 `experimental` 旗標。**

## 2. A 部｜〈未決事項〉頁：分層，不是搬家

### 2.1 結論

**不建議整頁移出網站。** 三項理由：

1. **與「供臨床試用」之目的相反**。試用端第一天必須知道者恰在此頁：
   **P-1**（canonical 仍 provisional，照現網址寫死 `meta.profile` 者於核定後全數要改，
   同時是 `qa.html` 大宗 `cannot be resolved` 之根因）、
   **M-5**（Core 係工作原案，必填欄位可能增減）、
   **M-8**（未審家族須保留原始 coding 照常交換、不得阻斷）。
   移走等同讓試用單位在不知情下投入開發；**揭露在使用者看得到的地方才是免責**。
2. **可追溯性缺口**。既發函文、委員回覆書與長官版簡報引用的是 `open-issues.html#m-5` 類**穩定錨點**；
   GitHub Issue 可被編輯、關閉、刪除，**無版次、不隨 IG 發佈產生快照**，
   作為對主管機關之正式揭露載體，可追溯性弱於隨版發佈之頁面。
   若確定以 GitHub 承接，應使用 **`docs/` 下之版本控管檔案**，而非 Issues。
3. **與既有裁示衝突**。JOB-23 §2.2（不刪〈快速入門〉〈未決事項〉）、
   JOB-26 §0（目標不是清空清單，而是逐項標示是否影響主管機關現在要公告的內容）。

> **主管的直覺有慣例支撐**：US Core v9.0.0 與 TW Core IG v1.0.0 均**無** known issues 專頁
> （JOB-26 §0 已查證）。惟該二者為**已定案之母規範**，本案為受託研製中草案，讀者與責任結構不同。

## 3. B 部｜治理分軌：讓國健署 Core 不與勞工區塊共命運

### 3.1 問題的實際形狀

> ⚠️ **本節已於 2026-08-20 更正。** 初稿把職安署列為本指引勞工區塊之「治理機關」，
> 屬**越權主張**——職安署未參與本案、未委任本指引、亦未對其內容表示意見。
> 本指引之主管機關**只有國民健康署一個**；《勞工健康保護規則》係**內容依據**，不是治理關係。
> 更正後之論述對國健署更有利（見 §3.2(3) 之引用句），且與本案「不越權背書」之寫作規範一致。

| 區塊 | 本指引之主管機關 | 內容依據 | IG 內對應物 |
|:--|:--|:--|:--|
| Core 最小共通上傳集（16 主項／21 列） | **國民健康署**（唯一） | 該署健檢上傳欄位規範 | `VS-CoreUploadSet` 及其子值集 |
| 勞工健檢與臨場服務（附表九／十／十一、健康管理分級、配工） | **同上，無第二個主管機關** | 《勞工健康保護規則》附表（該規則之主管機關為勞動部職安署，**惟本指引未受其委任**） | `VS-Appendix9/10-RequiredSet`、`TWHA-HealthManagementLevel` 等 |
| 技術決定（資源結構、切片、ConceptMap） | —（無行政效力） | 本團隊／次世代平臺辦公室 | 其餘 artifact |

**建議之範疇聲明**（納入 `conformance.md` §7 起首，並於 `index.md` 摘要一句）：

> 本指引之主管機關為**國民健康署**。勞工健康檢查項目係**依《勞工健康保護規則》附表九／十／十一之
> 項目表建立之結構化表達**，目的在於使勞工健檢資料得以同一標準交換，
> **非另立勞工健檢之規範，亦未受勞動部職業安全衛生署委任或授權**。
> 凡涉及該規則之法定解釋（保存期限起算點、附表十新增作業之施行日、情境資料集③之範疇），
> 本指引一律**僅載明規則要素並指向待釋示**，不代該署認定。

> **為何是「界定」而不是「忽略」**：完全不提職安署，日後若有人主張本指引在替該署訂規範，
> 文件裡沒有可引用的反證。**明文寫成非治理關係，比默默不提安全。**
> 此與 M-6（保存期限移出範疇）、JOB-27（存取控制移出範疇）採同一手法——
> 範疇界定要寫出來，不是省略。

真正的問題不在「兩個主管機關」，而在**三種不同效力層級的內容共用同一個 IG 層 `status`、
同一份未決清單、同一個版次**，致任一區塊未定即被讀成「整份還沒好」——
這才是「拖延」的來源，**不是勞工項目實際擋住了 Core**（§1.2 已證 Core 承載齊備）。

> **相依方向須先釐清（M-5）**：Core 係依國健署**工作原案**建立，正式公告版本待該署確認。
> **是 IG 等國健署，不是國健署等 IG。** 該署之欄位規範效力來自行政公告，
> **不因本指引仍為草案而受影響**。回覆時此點須置於第一段，否則形成互等的死結。
