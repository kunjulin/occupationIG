## 1. 問題（證據）

這份 IG 的一大優點是**誠實揭露未決事項**——但這些揭露目前**散落在各頁的引用區塊中**，
沒有單一入口。已發現的散落點：

| 編號 | 未決事項 | 出現位置 |
|:--|:--|:--|
| — | **canonical 為 provisional**：正式命名空間之核定機關與命名尚待確認 | `sushi-config.yaml` description、`README.md` |
| **M-5** | Core 係依國健署健檢上傳欄位之**工作原案**建立，正式公告版本尚待確認 | `index.md` §3 |
| **M-6** | 第 19 條保存期限**起算點**（檢查日／報告日／離職日）之解釋尚待確認 | `background.md` §3.1.1 |
| **G-2** | 驗證結果之意義界定：0 Error 不代表臨床適切性／法規符合性／情境完整性 | `README.md`、`index.md` |
| — | **已知盲區**：建置驗證不檢查 ValueSet 內 display 語意 | `README.md` |
| — | **③ 情境資料集尚未以值集形式定義**（backlog：`VS-Appendix9/10-RequiredSet`） | `index.md` §3、`general-exam.md` |
| — | **保存期限未結構化**（backlog：`ext-retention-period`） | `background.md` §3.1.1 |
| — | 附表十第 33–35 項（苯乙烯／甲苯／二甲苯）**過渡期聲明** | commit `ebaa196` 相關頁面 |
| — | 腰圍 `56086-2` 顯示名待以 loinc.org 覆核 | `README.md` 2026-07-23 條目 |
| — | 文件狀態：**工研院委託研製中之草案，尚未定稿** | `README.md`、各頁 |

問題不在於揭露不足，而在於：

1. **委員無法一頁掌握**「這份草案有哪些還沒定」——必須逐頁翻找引用區塊；
2. 同一件事在多處以**不同措辭**重複（例如草案狀態在 README、index、各頁都有不同版本的說法），
   之後修改容易漏改而產生矛盾；
3. 沒有編號體系的一致性（M-5、M-6、G-2 有編號，其餘沒有），也**看不出誰負責、何時可解**。

## 2. 目標與驗收標準

1. 新增 `open-issues.md`（建議標題「未決事項與已知限制 (Open Issues & Known Limitations)」），
   納入 `menu`，成為委員審查的單一入口。
2. 每筆未決事項統一格式：

   | 欄位 | 說明 |
   |:--|:--|
   | 編號 | 沿用既有 M-5／M-6／G-2，新項目續編（建議前綴分類：`M-` 模型、`G-` 治理、`T-` 術語、`P-` 發佈） |
   | 標題 | 一句話 |
   | 現況 | 目前 IG 怎麼處理（暫用什麼、假設什麼） |
   | 待決內容 | 具體要誰決定什麼 |
   | 決策所需輸入 | 例如「國健署正式公告」「勞動部函釋」「委託契約」 |
   | 影響範圍 | 哪些 artifact／頁面會隨之變動 |
   | 若決策不同的影響 | 需改多少（讓委員知道延後的成本） |
   | 狀態 | 待決／已決（附決議日期與依據） |

3. **各頁改為連結至該頁的對應條目**，不再各自重複完整說明
   （保留簡短提示 + 連結，例如「⚠️ 詳見[未決事項 M-5](open-issues.html#m-5)」）。
4. `README.md` 新增指向 `open-issues.md` 的連結。
5. 其他 JOB 執行中產生的未決事項（本目錄各 JOB 已標示者）一併登記：

| JOB-04 | 上傳語意採 `transaction` 或 `batch`（部分成功是否允許）——需平台端確認 |

5. 建立維護慣例：後續各 JOB 若遇需外部決策之事項，一律回填此頁（寫入 `CLAUDE.md`，見 JOB-12）。

## 5. 風險與注意事項

- **收攏時不要弱化既有警語**。目前各頁的警告文字寫得相當到位（尤其 README 對離線建置與
  display 盲區的警告），集中化的目的是「更容易找到」而非「淡化」。
  若集中後某頁失去必要警示，等於降低了品質。
- 「若決策不同的影響」欄位需誠實估算。這是委員判斷「可否先行採用」的關鍵資訊。
- 編號一旦公開就不宜變更（會影響外部引用），請一次定案。
