快速入門

快速入門 (Quick Start)：5 分鐘看懂這份指引

這一頁寫給誰：第一次接觸「FHIR」「IG」這些名詞的主管、業務單位、健檢機構管理者與計畫審查人員。 全文約 6 分鐘可讀完，不需要任何資訊背景。技術人員請直接看如何開始實作。

一、一句話說明

這是一份「臺灣勞工健康檢查資料該長什麼樣子」的國家級規格書草案，讓不同醫院、健檢機構、事業單位與主管機關之間，能用同一套格式交換勞工健檢資料。

本指引由衛生福利部委託財團法人工業技術研究院、長庚紀念醫院研製，依據《勞工健康保護規則》設計，並繼承國家核心標準「臺灣核心實作指引（TW Core IG v1.0.0）」。

二、三個名詞，用一個比喻講完

健檢資料交換就像寄一份公文給另一個機關。

名詞 白話說明 對應比喻
FHIR 國際通行的醫療資料交換標準（唸作 "fire"），規定醫療資料用什麼結構表達。 公文的格式規範：一定要有主旨、說明、正本、副本
IG（實作指引） 把國際標準「在地化」成某個特定用途的規格書。FHIR 本身很通用，IG 才是能照著做的版本。 某機關的公文製作手冊：這類公文主旨怎麼寫、附件放什麼
Profile / ValueSet IG 裡的兩種零件。Profile 規定「某一筆資料要有哪些欄位、哪些必填」；ValueSet 規定「這個欄位只能填清單裡的這幾個代碼」。 Profile＝表單樣板；ValueSet＝表單上的下拉選單選項

再補兩個會反覆出現的詞：

  • LOINC：檢驗項目的國際代碼。例如空腹血糖固定是 1558-6，不論哪家醫院都是同一碼——這樣接收端才知道這個數字是什麼。
  • Must Support（必須支援）：不是「一定要有值」，而是「系統一定要做得到送出與接收這個欄位」。沒做這項檢查時，要能明確標示「未執行」，而不是整欄消失。

關鍵理解：IG 不是一套系統，也不是一個平台。它是規格書。有了它，各家廠商各自開發的系統才有辦法對接；沒有它，每次串接都要重談一次格式。

三、為什麼要做這件事

目前國內健檢資料有三個結構性問題：

  1. 格式各自為政：同一項空腹血糖，A 院存在 PDF、B 院存在 Excel、C 院存在院內私有資料庫，欄位名稱與單位都不同。
  2. 跨院無法交換：勞工換工作、換醫院，前一次健檢結果拿不過來，也回不到健康存摺。
  3. 主管機關彙整困難：勞動部職安署、國民健康署、衛福部要做監測與流行病學分析時，必須逐案清洗資料。

本指引的目的，就是把「該交換什麼、用什麼代碼、怎麼包裝」一次講清楚，讓資料在產生的當下就是可交換的，而不是事後再做轉檔。

四、這份指引涵蓋什麼

以勞工健康檢查為核心，向兩個方向開放擴充：

臺灣勞工健康檢查交換實作指引 (TWHA IG)
├── Core：主管機關最小共通上傳集（國健署原案 21 列）
│      生活習慣（吸菸、嚼檳）／生理量測（身高體重腰圍血壓）／
│      基本檢驗（血脂、空腹血糖、肌酸酐、尿蛋白、肝炎）
├── 擴充一：特殊職類健檢
│      對應附表十危害作業（噪音／鉛／粉塵／有機溶劑／輻射／特定化學物質…）
└── 擴充二：一般健檢／成人預防保健
       國健署成人預防保健項目、社會決定因素（SDOH）問卷

同時涵蓋《勞工健康保護規則》的四張附表：附表八（臨場健康服務執行紀錄）、附表九（一般體格及健康檢查）、附表十（特殊體格及健康檢查，35 項具名作業／歸併為 12 個危害家族）、附表十一（健康檢查紀錄）；以及醫師健康管理分級（一～四級）與適性配工。

⚠️ 最容易被誤解的一件事：三種「資料集」不能混用

這是審查與溝通時最常出錯的地方，請務必分清楚：

  意義 白話
① IG 涵蓋範圍 本指引定義的全部結構與代碼（Core ∪ 擴充） 「這份規格書能表達什麼」
② Core 最小上傳集 主管機關制定的最小共通上傳欄位（21 列） 「至少要交換什麼」
③ 情境資料集 特定法定情境（如附表九、附表十某危害作業）依法應執行的完整項目 「該情境依法要做什麼」

① ≠ ② ≠ ③。 特別注意：

  • Core（21 列）不等於附表九，更不等於一份完整的勞工健檢。Core 是「最小上傳集」，不是「法定檢查項目表」。
  • 不能因為某項目不在 Core，就推論它不重要或可以不做。
  • Core 目前係依國健署健檢上傳欄位之工作原案建立，正式公告版本仍待主管機關確認（未決事項 M-5）。

七、還沒定案的事（外部依賴）

指引中所有需要外部機關決定的事項，都集中在未決事項與已知限制頁，每項載明現況、決定者、所需輸入、若決策不同的影響。目前主要待確認者包括：

  • Core 資料集的正式版本：國健署上傳欄位之正式公告版本（M-5）
  • canonical 命名空間：正式命名與核定機關尚待確認，現行位址為暫定（P-1）
  • 法規保存期限的起算點與結構化方式（M-6、M-7）
  • 雇主端資料隔離之實作機制：哪些健檢資訊雇主可見、如何隔離（M-10）
  • 部分檢驗代碼與 SNOMED CT 對照待臨床逐項確認（T-1、T-3）
  • 授權條款尚未宣告（P-2）

這些是外部依賴，不是團隊未完成的工作項目。本期的交付定位是：FHIR IG 草案 ＋ 驗證結果 ＋ 公開 IG 網站 ＋ 國家 IG 報備審查提案資料。

八、常見問題

Q：這是不是一套要買的系統？ 不是。這是規格書，沒有授權費、沒有伺服器。醫院與廠商各自依規格開發或改造既有系統。

Q：做了這個，醫院要換掉現有的 HIS/LIS 嗎？ 不用。通常做法是在既有系統外加一層轉換與輸出，把院內既有資料對映到本指引定義的格式。

Q：Core 只有 21 列，是不是把健檢簡化了？ 不是。21 列是「最小共通上傳集」，不是檢查項目表。法定該做的檢查一項都不會少，只是不見得每一項都在最小上傳集內。詳見上方三種資料集的說明。

Q：現在可以照著做了嗎？ 可以開始試作與評估，但不建議作為正式上線依據——版本為草案，內容得依共識會議、委員意見及主管機關規範調整。

Q：跟健康存摺、次世代平台的關係？ 本指引繼承 TW Core IG，與衛福部次世代數位醫療平臺的技術治理規範對齊，設計上即以能回饋至個人健康資料為前提。

如何開始實作

技術人員三步驟：

  1. 看懂範圍：資料模型 → FHIR 資源總覽（Profiles／Extensions／ValueSets／CodeSystems）
